# Review Sec-blind — Full Project Audit

Delegado a Opus 5.5 High com superpowers + secskills-core (crypto, vuln, review).
Data: 2026-11-17.

## 1. Direction Assessment

Arquitetura bate com o padrão de DRM comercial que o briefing promete: loader lazy-import + sentinel + HWID bind + AES-GCM payload + HMAC watermark + servidor Go com Redis/PG. Fases 1–6 estão coerentes entre si, o key-separation via HKDF-Expand foi resolvido em ambos os lados, e o fluxo end-to-end funciona. Decisões fundamentais estão no caminho certo e não precisam ser revisadas antes de novas features.

O que impede ship imediato é **execução**, não desenho: shutdown race entre `heartbeat` e `net`, enforcement incompleto de rate-limit, brute-force de license-key contra `/auth/login` sem consumir challenge, TLS terminado por nginx sem o server saber quem é o peer, e cerca de doze TODOs operacionais menores. Nenhum é re-arquitetura; são cortes para fechar as bordas antes do deploy comercial.

## 2. Findings

### CRITICAL

**[CRITICAL] Shutdown race: net::shutdown closes handles usadas pelo heartbeat thread**
File: `Project1/src/heartbeat.cpp:144-162` + `Project1/src/Main.cpp:203-205,219`
Problem: heartbeat::stop() espera só 10s. Se o thread estiver bloqueado dentro de WinHttpSendRequest/WinHttpReceiveResponse (TLS handshake + round-trip pode passar disso facilmente), stop() retorna com o thread vivo; Main.cpp então chama net::shutdown() que fecha s_conn/s_session, e o thread acorda tocando handles liberadas.
Impact: UAF / crash em produção durante shutdown normal com rede lenta ou quando o server pendura.
Fix: antes de net::shutdown(), pular o join se timeout e trocar por net::cancel_in_flight() que chama WinHttpCloseHandle(hRequest) no handle corrente (mantido em s_cs). Ou aumentar o timeout e deixar o thread sinalizar completed_event antes de net::shutdown prosseguir.

**[CRITICAL] /auth/login: brute-force de license_key sem gastar challenge**
File: `server/internal/api/api.go:205-233`
Problem: a ordem de checks é (1) LicenseByKey → (2) banned/kill → (3) TakeChallenge (GETDEL) → (4) HMAC. Se o license é desconhecido, retorna 401 ANTES de consumir o nonce. Um atacante com 1 challenge válido para seu HWID pode testar N chaves de licença dentro dos 60s de TTL.
Impact: com rate-limit a 30 rpm por IP, dá ~1800 tentativas por hora por IP; via IPv6/botnet inviabiliza enforcement.
Fix: TakeChallenge primeiro (GETDEL é one-shot) e só depois LicenseByKey; se o challenge não bate, 401 sem vazar nada.

**[CRITICAL] Rate-limit não enforçado em /heartbeat, /payload/fetch, /rpc/call**
File: `server/internal/api/api.go:343-614`
Problem: campos per_ip_rpm/per_hwid_rpm lidos mas só /auth/challenge e /auth/login chamam s.rateLimit. Qualquer cliente com token válido pode martelar /payload/fetch (AES-GCM + HKDF-Expand + Redis + PG a cada chamada).
Impact: DoS trivial com licença legítima.
Fix: s.rateLimit(ctx, clientIP(r), sess.HWID) após resolver sess nos três handlers; limite menor em /payload/fetch (ex: 6 rpm).

### HIGH

**[HIGH] Cert pin dual aponta para o mesmo hash self-signed de integration**
File: `Project1/src/net.cpp:161-162`
Fix (pre-deploy): substituir ambos por hashes reais (current + backup) e adicionar assert em release build.

**[HIGH] TLS plain-HTTP sem forma de detectar bypass do nginx**
File: `server/cmd/server/main.go:94-103`
Fix: listen 127.0.0.1 only + firewall, OU TLS nativo no http.Server, OU rejeitar se X-Forwarded-Proto != "https".

**[HIGH] HWID bind TOCTOU: cooldown read e upsert não são atômicos**
File: `server/internal/api/api.go:260-286`
Fix: transação com SELECT ... FOR UPDATE, ou upsert condicional (UPDATE ... WHERE last_change < now() - interval '30 days').

**[HIGH] /rpc/call sem anti-replay**
File: `server/internal/api/api.go:537-614`
Fix: adicionar nonce no request, armazenar `rpc_nonce:<token>:<nonce>` no Redis com TTL = 2*skew.

**[HIGH] Heartbeat renova TTL mesmo com kill=true**
File: `server/internal/api/api.go:407-417`
Fix: se killed, DeleteSession e não chamar RefreshSession/RememberLatestToken.

**[HIGH] fgets pode truncar license key >127 chars sem feedback**
File: `Project1/src/Main.cpp:70-77`
Fix: buffer 256 ou std::getline.

**[HIGH] Nenhum graceful shutdown no servidor**
File: `server/cmd/server/main.go:103`
Fix: signal.Notify + hs.Shutdown com context 30s.

**[HIGH] s_running / s_reason acessados cross-thread sem atomic/barrier**
File: `Project1/src/heartbeat.cpp:32,43-100,164` + `Project1/src/sentinel.cpp:27-83`
Fix: std::atomic<bool> com acquire/release.

**[HIGH] Observabilidade zero no server**
File: `server/*`
Fix: middleware log/slog estruturado; counters no abuse_log para HMAC-fail em /heartbeat e /rpc/call.

### MEDIUM

- **Timing side-channel: license existence leaks** (`api.go:205-222`) — colapsar mensagens de erro.
- **Server watermark TTL 24h sem invalidação em kill** (`api.go:517`) — documentar ou reduzir para 1h.
- **Clock rollback bypassa watermark expiry** (`watermark.cpp:144-151`) — limitação documentada.
- **HWID cooldown bloqueia primeiro rebind por 30d** (`postgres.go:84-89` + `api.go:277`) — só setar last_change quando curBind != req.HWID.
- **PRK (session_key) trafega e persiste em Redis em base64** (`api.go:322`, `redis.go:38-52`) — documentar como secret-tier storage, ACL + TLS + rotação.
- **HKDFExpand descarta erro de io.ReadFull** (`hkdf.go:28-33`) — retornar error.
- **http.MaxBytesReader com nil ResponseWriter** (`api.go:95`) — passar w para 413 correto.
- **Server não trata DNS/connect do Postgres em startup** (`main.go:66-70`) — pool.Ping(ctx) + fatal.
- **Canonical delimiter '|' assume método sem pipe** (`rpc.cpp:76-82`) — whitelist no server.

### LOW

- **Watermark hwid field: doc diz SHA-256(hex_string), código usa hex-decode** (`SERVER_SPEC.md:174` vs `watermark.cpp:129-133`) — editar doc.
- **LogAbuse detached context pode vazar durante shutdown** (`postgres.go:118-126`) — aceitar.
- **isValidHWID aceita strings case-sensitive sem erro específico** (`api.go:125-136`) — sem ação.
- **rpc.cpp parâmetro chamado session_key mas espera k_rpc** (`rpc.h` + `rpc.cpp:53-57, 85-87`) — renomear para rpc_key.
